# Wasfati

## 1 ما هو المشروع

وصفتي (Wasfati) تطبيق ويب لإدارة مرضى وأدوية وزيارات ووصفات. يفحص تداخلاً نصياً بين دواء مقترح وأدوية المريض الحالية وحساسياته، ويقترح أدوية حسب كلمات في الأعراض والتشخيص. التخزين SQLite عبر Flask-SQLAlchemy. الملف الافتراضي `instance/wasfati.db`.

الوصف في README السابق عن مساعدة الطبيب على تنظيم الوصفة وفحص التداخل يبقى مطابقاً لوظائف `app.py` و`utils.py`.

## 2 لمن هذا المشروع

مستخدم واحد من جدول `users` بعد تسجيل الدخول. النموذج في `models.py` يسمّي الفئة «نموذج المستخدم (الأدمن)». لا أدوار متعددة في الأعمدة. كل الصفحات ما عدا `/login` و`/logout` محمية بـ `login_required`.

الطبيب في وصف README السابق هو مستخدم هذا الحساب. لا جدول أطباء منفصل. اسم الطبيب على الزيارة حقل نصي `visits.doctor_name`.

## 4 أمثلة واقعية

عند أول إنشاء والجداول فارغة من الأدوية، `add_sample_data` في `models.py` يدرج خمسة أدوية موسومة «تجريبي»: باراسيتامول، أموكسيسيلين، أوميبرازول، ميتفورمين، أملوديبين، مع فئات وجرعات وتداخلات وموانع كنصوص JSON.

مريضان تجريبيان برقمي ملف `P001` و`P002`. مستخدم باسم `admin` يُنشأ داخل نفس الدالة إن كان جدول المستخدمين فارغاً. كلمة المرور تُعيَّن في الكود ولا تُنسخ هنا. سكربت `create_admin.py` ينشئ المستخدم نفسه أو يحدّث تجزئة كلمة المرور.

اقتراح الوصفة يطابق كلمات عربية:

| الفئة | أمثلة كلمات في `utils.py` |
| --- | --- |
| مسكنات | ألم، صداع، وجع، حرارة، سخونة |
| مضادات حيوية | التهاب، عدوى، بكتيريا، صديد |
| أدوية الجهاز الهضمي | حموضة، معدة، قرحة، حرقة، غثيان |
| أدوية السكري | سكر، سكري، جلوكوز |
| أدوية القلب والضغط | ضغط، قلب، ضغط دم |

إن لم تُطابق أي كلمة تُستخدم كل الفئات. الأدوية غير `available` تُستبعد. الجرعة المقترحة أول عنصر في قائمة الجرعات، أو النص «حسب إرشادات الطبيب».

مثال README السابق ذكر إيبوبروفين مع الصداع. إيبوبروفين غير موجود في قائمة `sample_drugs` الحالية. الصداع يطابق فئة المسكنات، والدواء التجريبي في تلك الفئة هو باراسيتامول.

## 5 رحلة الاستخدام

1. `python app.py` يستدعي `init_db` فينشئ مجلد `instance` والجداول، ويبذر البيانات إن لم توجد أدوية.
2. فتح `http://127.0.0.1:5000` يحوّل غير المسجّل إلى `/login` لأن `/` محمي.
3. بعد الدخول تُعرض `index.html`.
4. إضافة مريض تتحقق من رقم الملف الفريد والعمر والجنس.
5. شاشة الوصفة ترسل أعراضاً وتشخيصاً إلى واجهة الاقتراح ثم تفحص التداخل قبل الحفظ.
6. الزيارة تُحفظ في `visits` والوصفة JSON داخل العمود `prescription`.

## 17 الخادم الخلفي

`app.py` يحمّل `Config` ثم `init_db(app)`. نماذج SQLAlchemy في `models.py`. منطق السلامة في `utils.py` منفصل عن المسارات.

## 18 تدفق الطلب

```
POST /patient/new
  -> login
  -> validate_patient_data
  -> رفض رقم ملف مكرر
  -> حفظ Patient مع أدوية وحساسيات كـ JSON
  -> رد JSON نجاح أو أخطاء 400

POST /api/suggest-prescription
  -> قراءة الأعراض والتشخيص والمريض
  -> suggest_prescription
  -> ترتيب حسب الشدة: none ثم low ثم medium ثم high
```

بحث المرضى في القائمة يبني نمط `LIKE` من نص البحث عبر SQLAlchemy.

`SQLALCHEMY_TRACK_MODIFICATIONS = False`.

## 21 المصادقة

نموذج دخول بحقول `username` و`password`. النجاح يضع `user_id` و`username` و`full_name` في الجلسة. الفشل رسالة فلاش: «اسم المستخدم أو كلمة المرور غير صحيحة». الخروج `session.clear()`.

مفتاح الجلسة من المتغير `SECRET_KEY` أو سلسلة احتياطية داخل `config.py`. لا تُنسخ السلسلة هنا.

## 22 الأمان

الموجود:

- تجزئة كلمة المرور عبر Werkzeug عند `set_password`.
- الصفحات الوظيفية خلف الجلسة.
- تحقق عمر وجنس وحقول مطلوبة.
- رفض رقم ملف مكرر.
- حد حجم جسم الطلب `MAX_CONTENT_LENGTH` يساوي 16 ميغابايت.
- استعلامات النماذج عبر SQLAlchemy.

غير الموجود في الملفات الحالية:

- CSRF على النماذج.
- حد لمحاولات الدخول.
- أدوار أدق من حساب نشط واحد.
- `debug=True` في التشغيل المحلي المباشر.

فحص التداخل يقارن سلاسل بعد `lower`. مطابقة الحساسية تتم إذا ظهرت سلسلة الحساسية داخل اسم الدواء أو العكس. هذا سلوك النص الحالي في `check_drug_interactions`.

تسجّل الدخول، تضيف مريضاً برقمه وأدويته وحساسياته، ثم تفتح الوصفة. النظام يقترح أدوية من الفئات القريبة من كلمات الأعراض، ويعرض تحذيراً إذا تشابه اسم الدواء مع حساسية أو مع دواء يتناوله المريض. احفظ الزيارة ليبقى السجل على ملف المريض.
