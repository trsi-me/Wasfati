# وصفتي - نظام الوصفات الطبية الذكي

## ما هو المشروع؟

**وصفتي** هو نظام برمجي يساعد الأطباء على إنشاء وإدارة الوصفات الطبية بطريقة آمنة. تخيل أنك طبيب وتريد كتابة وصفة طبية لمريض - هذا النظام يساعدك على:

- **تجنب الأخطاء**: يفحص تلقائياً إذا كان هناك تداخل بين الأدوية (مثل: دواءين لا يجب تناولهما معاً)
- **تنظيم المعلومات**: يحفظ بيانات المرضى والأدوية في مكان واحد
- **اقتراحات ذكية**: يقترح عليك أدوية مناسبة بناءً على الأعراض التي يدخلها المريض

### مثال واقعي

لنفترض أن مريضاً يأتي بشكوى من صداع شديد. بدلاً من أن تبحث في كتب الأدوية، النظام:
1. يسألك عن الأعراض (صداع)
2. يقترح عليك أدوية مناسبة (مثل: باراسيتامول)
3. يفحص إذا كان المريض يتناول أدوية أخرى قد تتعارض مع الدواء المقترح
4. يحفظ الوصفة في ملف المريض تلقائياً

## المصطلحات التقنية المبسطة

### Backend (الخلفية)
**ما هو؟** الجزء الذي لا تراه من التطبيق - مثل المطبخ في المطعم.  
**مثال**: عندما تضغط زر "حفظ" في النظام، الـ Backend هو الذي يحفظ البيانات في قاعدة البيانات.

### Frontend (الواجهة)
**ما هو؟** الجزء الذي تراه وتتفاعل معه - مثل قائمة الطعام في المطعم.  
**مثال**: الأزرار، النماذج، الألوان - كل ما تراه على الشاشة.

### قاعدة البيانات (Database)
**ما هو؟** مكان تخزين المعلومات بشكل منظم - مثل دفتر ملاحظات إلكتروني.  
**مثال**: عندما تضيف مريضاً جديداً، تُحفظ معلوماته في قاعدة البيانات لتتمكن من العودة إليها لاحقاً.

### Flask
**ما هو؟** أداة برمجية لبناء تطبيقات الويب بلغة Python - مثل مجموعة الأدوات التي تساعدك على بناء منزل.  
**مثال**: بدلاً من كتابة كل شيء من الصفر، Flask يوفر لك أدوات جاهزة لإنشاء صفحات الويب.

### SQLite
**ما هو؟** نوع من قواعد البيانات البسيطة - مثل ملف Excel لكن أكثر تطوراً.  
**مثال**: يحفظ جميع بيانات المرضى والأدوية في ملف واحد اسمه `wasfati.db`.

### API (واجهة برمجة التطبيقات)
**ما هو؟** طريقة للتواصل بين أجزاء التطبيق - مثل لغة مشتركة بين المكونات.  
**مثال**: عندما تبحث عن دواء، الـ Frontend يرسل طلباً للـ Backend عبر الـ API للحصول على قائمة الأدوية.

## الميزات الرئيسية

### 1. إدارة المرضى
- حفظ بيانات المرضى (الاسم، العمر، الجنس)
- حفظ الأدوية الحالية التي يتناولها المريض
- حفظ الحساسيات (مثل: حساسية من البنسلين)

### 2. قاعدة بيانات الأدوية
- معلومات عن كل دواء (الاسم، الفئة، الجرعات)
- قائمة التداخلات (أي أدوية لا يجب تناولها مع هذا الدواء)
- الموانع (متى لا يجب استخدام هذا الدواء)

### 3. فحص التداخلات
- يفحص تلقائياً إذا كان هناك تداخل بين الأدوية في الوصفة
- ينبهك إذا كان المريض لديه حساسية من دواء معين
- يتحقق من الموانع (مثل: دواء لا يجب إعطاؤه للحامل)

### 4. اقتراحات ذكية
- بناءً على الأعراض التي تدخلها، يقترح أدوية مناسبة
- مثال: إذا أدخلت "صداع"، قد يقترح "باراسيتامول" أو "إيبوبروفين"

## التثبيت والتشغيل المحلي

### الخطوة 1: تثبيت المكتبات المطلوبة

المكتبات هي أدوات برمجية جاهزة يحتاجها المشروع للعمل. مثل شراء الأدوات قبل بناء منزل.

```bash
pip install -r requirements.txt
```

**ما الذي يحدث هنا؟** الأمر يقرأ ملف `requirements.txt` الذي يحتوي على قائمة المكتبات المطلوبة (مثل Flask) ويقوم بتثبيتها.

### الخطوة 2: تشغيل التطبيق

```bash
python app.py
```

**ما الذي يحدث هنا؟** الأمر يبدأ تشغيل التطبيق على جهازك المحلي.

### الخطوة 3: فتح المتصفح

افتح المتصفح وانتقل إلى:
```
http://127.0.0.1:5000
```

**شرح العنوان:**
- `http://` = بروتوكول الاتصال (مثل لغة التواصل)
- `127.0.0.1` = عنوان جهازك المحلي (يعني "هذا الجهاز")
- `5000` = رقم المنفذ (مثل رقم الباب)

## النشر على Heroku

### ما هو Heroku؟

**Heroku** هو منصة سحابية (Cloud Platform) تتيح لك نشر تطبيقات الويب على الإنترنت. فكر فيه كـ:

- **استضافة مجانية/مدفوعة** لتطبيقات الويب
- **خادم بعيد** (Remote Server) يعمل عليه تطبيقك 24/7
- **عنوان ويب** يمكن لأي شخص الوصول إليه من أي مكان

**مثال واقعي:**
- **محلياً**: تطبيقك يعمل فقط على جهازك، لا يمكن لأحد آخر الوصول إليه
- **على Heroku**: تطبيقك يعمل على خوادم Heroku، يمكن لأي شخص في العالم الوصول إليه عبر رابط مثل `https://wasfati.herokuapp.com`

### لماذا Heroku؟

1. **سهولة الاستخدام**: لا تحتاج لمعرفة تقنية عميقة في إدارة الخوادم
2. **مجاني للبداية**: يقدم خطة مجانية للبدء
3. **تحديث سهل**: يمكنك تحديث التطبيق بضغطة زر
4. **دعم Python**: يدعم تطبيقات Python/Flask بشكل ممتاز

### متطلبات النشر على Heroku

قبل النشر، تأكد من وجود:

1. **حساب على Heroku**: سجل في [heroku.com](https://www.heroku.com)
2. **Heroku CLI**: أداة سطر الأوامر للتعامل مع Heroku
3. **Git**: نظام إدارة الإصدارات (يجب أن يكون المشروع في مستودع Git)

### خطوات النشر التفصيلية

#### الخطوة 1: تثبيت Heroku CLI

**ما هو Heroku CLI؟** أداة تسمح لك بالتحكم في تطبيقات Heroku من سطر الأوامر.

**كيفية التثبيت:**
- اذهب إلى [devcenter.heroku.com/articles/heroku-cli](https://devcenter.heroku.com/articles/heroku-cli)
- حمّل النسخة المناسبة لنظامك (Windows/Mac/Linux)
- ثبتها كأي برنامج عادي

**التحقق من التثبيت:**
```bash
heroku --version
```
إذا ظهر رقم الإصدار، يعني التثبيت نجح.

#### الخطوة 2: تسجيل الدخول إلى Heroku

```bash
heroku login
```

**ما الذي يحدث؟**
- يفتح المتصفح تلقائياً
- سجل دخولك بحساب Heroku
- بعد تسجيل الدخول، يعود الأمر إلى سطر الأوامر

#### الخطوة 3: تهيئة Git (إذا لم يكن موجوداً)

**ما هو Git؟** نظام لإدارة الإصدارات - يحفظ تاريخ جميع التغييرات في مشروعك.

**التحقق من وجود Git:**
```bash
git --version
```

**إذا لم يكن موجوداً:**
- حمّل Git من [git-scm.com](https://git-scm.com)
- ثبتّه

**تهيئة Git في المشروع:**
```bash
git init
git add .
git commit -m "Initial commit"
```

**شرح الأوامر:**
- `git init` = يبدأ مستودع Git جديد في المجلد الحالي
- `git add .` = يضيف جميع الملفات للمرحلة (Staging)
- `git commit -m "..."` = يحفظ التغييرات مع رسالة وصفية

#### الخطوة 4: إنشاء تطبيق Heroku

```bash
heroku create wasfati-app
```

**ما الذي يحدث؟**
- ينشئ تطبيقاً جديداً على Heroku باسم `wasfati-app`
- يعطيك رابطين:
  - رابط التطبيق: `https://wasfati-app.herokuapp.com`
  - رابط Git: `https://git.heroku.com/wasfati-app.git`

**ملاحظة:** الاسم يجب أن يكون فريداً (غير مستخدم من قبل). إذا كان الاسم مستخدماً، جرّب اسم آخر.

#### الخطوة 5: إعداد قاعدة البيانات

**المشكلة:** Heroku لا يدعم SQLite بشكل جيد (لأن الملفات تُحذف عند إعادة التشغيل).

**الحل:** استخدام PostgreSQL (نوع آخر من قواعد البيانات يدعمه Heroku).

**إضافة PostgreSQL:**
```bash
heroku addons:create heroku-postgresql:hobby-dev
```

**ما الذي يحدث؟**
- يضيف قاعدة بيانات PostgreSQL مجانية للتطبيق
- يضيف متغير بيئة `DATABASE_URL` تلقائياً

**تعديل config.py:**
يجب تعديل `config.py` لدعم PostgreSQL:

```python
import os
import re

BASE_DIR = os.path.abspath(os.path.dirname(__file__))

class Config:
    SECRET_KEY = os.environ.get('SECRET_KEY') or 'wasfati-secret-key-2024-medical-prescription'
    
    # دعم PostgreSQL على Heroku و SQLite محلياً
    database_url = os.environ.get('DATABASE_URL')
    if database_url:
        # Heroku يستخدم PostgreSQL
        if database_url.startswith('postgres://'):
            database_url = database_url.replace('postgres://', 'postgresql://', 1)
        SQLALCHEMY_DATABASE_URI = database_url
    else:
        # محلياً استخدم SQLite
        SQLALCHEMY_DATABASE_URI = 'sqlite:///' + os.path.join(BASE_DIR, 'instance', 'wasfati.db')
    
    SQLALCHEMY_TRACK_MODIFICATIONS = False
    ITEMS_PER_PAGE = 20
    MAX_CONTENT_LENGTH = 16 * 1024 * 1024
    STATIC_FOLDER = os.path.join(BASE_DIR, 'static')
    TEMPLATE_FOLDER = os.path.join(BASE_DIR, 'templates')
```

**شرح التعديل:**
- يتحقق إذا كان هناك `DATABASE_URL` (موجود على Heroku)
- إذا كان موجوداً، يستخدمه (PostgreSQL)
- إذا لم يكن موجوداً، يستخدم SQLite (محلياً)

#### الخطوة 6: إضافة gunicorn إلى requirements.txt

**ما هو gunicorn؟** خادم ويب لتطبيقات Python - مثل محرك السيارة، يجعل التطبيق يعمل بشكل صحيح على Heroku.

**إضافة gunicorn:**
افتح `requirements.txt` وتأكد من وجود:
```
gunicorn
```

إذا لم يكن موجوداً، أضفه في نهاية الملف.

#### الخطوة 7: إنشاء ملف Procfile

**ما هو Procfile؟** ملف يخبر Heroku كيف يبدأ تطبيقك.

**المحتوى:**
```
web: gunicorn app:app
```

**شرح المحتوى:**
- `web:` = نوع العملية (عملية ويب)
- `gunicorn` = الأمر الذي سيتم تشغيله
- `app:app` = أول `app` هو اسم الملف (`app.py`)، الثاني هو اسم المتغير (`app = Flask(...)`)

**ملاحظة:** الملف موجود بالفعل في المشروع.

#### الخطوة 8: إضافة runtime.txt (اختياري)

**ما هو runtime.txt؟** يحدد إصدار Python الذي سيستخدمه Heroku.

**إنشاء الملف:**
أنشئ ملف `runtime.txt` في المجلد الرئيسي:
```
python-3.10.6
```

**لماذا؟** لضمان استخدام نفس إصدار Python الذي تستخدمه محلياً.

#### الخطوة 9: رفع الكود إلى Heroku

```bash
git add .
git commit -m "Prepare for Heroku deployment"
git push heroku main
```

**شرح الأوامر:**
- `git add .` = يضيف جميع التغييرات
- `git commit -m "..."` = يحفظ التغييرات
- `git push heroku main` = يرفع الكود إلى Heroku ويبدأ النشر

**ما الذي يحدث أثناء النشر؟**
1. Heroku يستقبل الكود
2. يقرأ `requirements.txt` ويثبت جميع المكتبات
3. يقرأ `Procfile` ويعرف كيف يبدأ التطبيق
4. يبدأ تشغيل التطبيق
5. يعطيك رابط التطبيق

#### الخطوة 10: تهيئة قاعدة البيانات على Heroku

```bash
heroku run python
```

ثم في Python:
```python
from app import app
from models import db, init_db
init_db(app)
exit()
```

**أو** إذا كان لديك سكريبت تهيئة:
```bash
heroku run python init_db.py
```

**ما الذي يحدث؟** ينشئ جداول قاعدة البيانات على Heroku (مثل إنشاء الملفات لأول مرة).

#### الخطوة 11: فتح التطبيق

```bash
heroku open
```

**أو** افتح الرابط مباشرة:
```
https://wasfati-app.herokuapp.com
```

### تحديث التطبيق على Heroku

عندما تقوم بتعديلات وتريد تحديث التطبيق:

```bash
git add .

git push heroku main
```

**ما الذي يحدث؟** Heroku يستقبل التحديثات ويعيد نشر التطبيق تلقائياً.

### عرض السجلات (Logs)

لمعرفة ما يحدث في التطبيق:

```bash
heroku logs --tail
```

**متى تستخدمه؟** عندما يواجه التطبيق مشكلة وتريد معرفة السبب.

### ملاحظات مهمة عن Heroku

1. **الخطة المجانية:** Heroku ألغى الخطة المجانية، لكن يقدم خطة أساسية بسعر منخفض
2. **إعادة التشغيل:** التطبيق قد ينام بعد فترة عدم استخدام (في الخطة المجانية القديمة)
3. **قاعدة البيانات:** PostgreSQL على Heroku تحذف البيانات بعد 30 يوم في الخطة المجانية (إذا كانت متوفرة)
4. **الملفات المؤقتة:** أي ملفات تحفظها في النظام قد تُحذف عند إعادة التشغيل

## التقنيات المستخدمة

- **Flask**: إطار عمل لبناء تطبيقات الويب بلغة Python
- **SQLAlchemy**: أداة للتعامل مع قواعد البيانات
- **SQLite**: قاعدة بيانات بسيطة (محلياً)
- **PostgreSQL**: قاعدة بيانات متقدمة (على Heroku)
- **HTML/CSS/JavaScript**: لبناء الواجهة
- **Gunicorn**: خادم ويب لتشغيل التطبيق على Heroku
